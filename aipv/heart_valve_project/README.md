# Heart Valve Project: VALVEBENCH + PINNVALVE

This workspace contains two things:

- **VALVEBENCH**: a reproducible synthetic benchmark for predicting pediatric pulmonary-valve annulus growth from anthropometrics, with multiple baseline models, leakage-safe splits, and an in-distribution/out-of-distribution evaluation protocol.
- **PINNVALVE**: a physics-informed neural network that predicts scaffold expansion (diameter, constraint stress, martensite fraction) from scaffold design parameters, testing whether a physics-based training signal improves generalization and latent-state recovery beyond a purely data-driven model.

**How they connect**: VALVEBENCH establishes the reproducible evaluation infrastructure (splits, metrics, ID/OOD protocol, multi-seed statistics) that PINNVALVE's scaffold-mechanics model is built and evaluated on top of. VALVEBENCH's baselines answer "what's achievable with standard ML on this benchmark"; PINNVALVE's ablation answers "does adding a physics prior help beyond that."

This README states plainly what's implemented and what isn't, and reports the actual numbers this codebase produces — including a finding that did **not** hold up under scrutiny (see "What changed on the second audit pass" below). If you're evaluating this project, start there.

## 1. What VALVEBENCH is

A benchmark task (`valvebench.tasks.annular_growth_12mo`): predict a pediatric patient's 12-month pulmonary annulus diameter from four baseline anthropometric features (height, weight, BMI, BSA), on a frozen synthetic dataset (`v0.1`), with:

- A leakage-safe, patient-level train/test split (`valvebench.datasets.splits.create_group_splits`).
- An **in-distribution vs. out-of-distribution** evaluation: training data is drawn only from `INTERIOR_AGE_RANGE_YRS` (3–13 years); the OOD test set is drawn only from the excluded age extremes (infants under 3, adolescents over 13) — ages the model never saw. This tests extrapolation, not interpolation.
- Multi-seed evaluation (`valvebench.tasks.run_multi_seed`): every leaderboard number is a **mean ± standard deviation across 5 seeds**, not a single lucky split.
- Six baseline models, and a controlled-grid physiological monotonicity check (does the model predict a larger annulus for a larger body size, holding everything else fixed?).

## 2. What PINNVALVE is

`valvebench.models.pinn_scaffold.ScaffoldPINN`: a neural network that maps a scaffold design vector (suture count, material stiffness, dissolution rate, fold angle) and time to three outputs — diameter, constraint stress (σ), and martensite volume fraction (ξ). Only diameter is ever supervised by the training loss; σ and ξ are latent state the network must infer purely through physics residuals derived from the full Brinson (1993) / Auricchio–Sacco (1997) phase-fraction constitutive model for shape-memory alloys.

## 3. The scientific question

**Does adding a physics-based training signal (vs. a purely data-driven network of the same architecture) improve (a) prediction accuracy under distribution shift, and (b) recovery of physical state that was never directly observed?**

This is tested as an ablation: identical network architecture, identical data, identical training budget — the only difference is `physics_weight` (0 = data-only, >0 = physics-informed).

## 4. What data are synthetic (all of it) and how it's generated

**Everything numeric in this repository's leaderboards and ablations is synthetic.** No real patient data, no real clinical measurements, no real nitinol test data are used anywhere. Two generators, both in `valvebench/datasets/synthetic.py`:

- **Patient growth**: baseline annulus diameter scales with `sqrt(BSA)` (the same qualitative basis real pediatric echo Z-score methodology uses), and 12-month growth rate depends on age, sex, and BSA via an exponential-decay/log-BSA model. Height and weight are age-correlated (not independent draws — see §13 for why this was a real bug that got fixed). Coefficients are illustrative, not fit to a real published equation.
- **Scaffold expansion**: driven by the actual Brinson/Auricchio-Sacco constitutive model (not a toy formula) — a constraint stress relaxes exponentially as sutures dissolve, and the martensite fraction follows real transformation kinetics as that stress crosses reverse-transformation thresholds. Material constants (elastic moduli, transformation stresses, max transformation strain) are representative literature values for superelastic nitinol, not calibrated against a measured sample.

Full derivations and honesty caveats are in each generator function's docstring and in `valvebench/physics/sma_constitutive.py`.

## 5. Models compared

| Model | What it is |
| --- | --- |
| `linear`, `ridge` | Closed-form / L2-regularized linear regression (features standardized for `ridge`, so `alpha` means the same thing regardless of a feature's raw scale) |
| `mlp` | scikit-learn `MLPRegressor` (features **and targets** standardized — see §13, this fixed a real convergence bug) |
| `gbm`, `gbm_monotone` | `HistGradientBoostingRegressor`; `gbm_monotone` constrains predictions non-decreasing in every feature |
| `pinn` | A physics-informed MLP with a monotonic-growth penalty (the simpler `valvebench/physics/sma.py` relaxation model — patient anthropometrics don't carry scaffold design parameters, so the full constitutive model isn't applicable here) |
| `literature_regression` | **Not runnable out of the box.** Requires real coefficients from a published closed-form formula (e.g. Hoashi/Zhang), which this environment has no verified access to. Raises immediately rather than using fabricated numbers. |

No model was hyperparameter-searched against the leaderboard's own test set. `mlp`'s `max_iter` was raised from 500 to 2000 as a correctness fix (500 was empirically insufficient once the underlying signal was strong enough to actually be fit — it produced R² ≈ −7 before the fix), not as tuning for advantage.

## 6. How patient-level splitting works

`create_group_splits`/`create_leakage_safe_splits` (`valvebench/datasets/splits.py`) split by `Patient_ID` (or `sample_id` for scaffold trajectories, which have 5 rows per design) using `GroupShuffleSplit`/`StratifiedShuffleSplit`, guaranteeing every row belonging to one patient/design stays in exactly one split. Verified by `tests/test_leakage.py`.

## 7. What OOD evaluation means here

Two independent OOD protocols, one per task, both testing extrapolation beyond the training distribution's support:

- **Patient growth**: train on ages 3–13, test on the excluded extremes (`generate_synthetic_id_ood_split`).
- **Scaffold expansion**: train on an interior sub-box of the 4-D design-parameter space (`INTERIOR_PARAM_RANGES`), test on the 16 corners of the full space (`ood_corner_dataset_sma`) — every corner lies outside the training box by construction.

For PINNVALVE specifically, there's a **third**, separate dataset (`ood_shell_dataset`, a random sample from outside the training box) used only for hyperparameter selection, so the final reported OOD numbers are never touched during tuning. This separation matters — see §13.

## 8. What physics is incorporated

`valvebench/physics/sma_constitutive.py` implements:

- **Kinetics residual**: Brinson's cosine reverse-transformation law, `ξ(σ) = ξ_M0/2 · [cos(π·(σ_As−σ)/(σ_As−σ_Af)) + 1]`, relating martensite fraction to constraint stress.
- **Constitutive residual**: the Auricchio-Sacco stress-strain closure, `σ = E(ξ)·(ε − ξ·ε_L)`.
- Both are checked in unit tests against hand-constructed analytic cases (`tests/test_sma_constitutive.py`) where the residual must be exactly zero by construction.
- Plus monotonicity/yield-cap residuals (diameter shouldn't shrink; shouldn't exceed a design's saturation cap).

## 9. What the physics model does NOT include

- No forward (austenite→martensite) transformation kinetics — only the reverse direction, matching the single crimped-to-relaxed loading path this project models.
- No temperature dependence — isothermal.
- No literal claim that material-level strain equals device-level diameter change: a real strut/lattice scaffold amplifies small material strains into large device deformations, which would require the actual strut geometry (out of scope). The generator maps a physically-derived *recovery fraction* onto a separately-modeled device-level diameter range instead — see `sma_constitutive.py`'s docstring.
- Material constants are representative literature values, **not calibrated against a measured nitinol sample**.
- No coupling to a real FEM/COMSOL simulation anywhere in this repository.

```bash

# One command: every model, 5 seeds, ID+OOD, regenerates leaderboard.md
```

Every generator, split, and model accepts an explicit `seed`; the multi-seed harnesses (`run_multi_seed`, `run_ablation_multi_seed`) fix the seed list in code so results are exactly reproducible. `experiments/pinnvalve_ablation_results.json` is the raw per-seed data behind every aggregate number reported here.

## 12. Limitations (stated explicitly, not buried)

- **All data are synthetic.** No claim is made about real pediatric or nitinol outcomes.
- **VALVEBENCH is the synthetic-data-only benchmark.** The larger "open public benchmark" version of the original spec — MMWHS/ImageCHD/SegTHOR/NIH-3D ingestion actually populated with data, real CDC/WHO-derived training features, transcribed Pettersen/Zilberman tables, a live literature-regression baseline — is **not implemented**. Loaders/scaffolding exist (`valvebench/datasets/imaging/`, `valvebench/datasets/literature_tables.py`) but require data this environment doesn't have verified access to.
- **PINNVALVE's headline diameter-accuracy claim did not survive a corrected evaluation methodology** (see §13) — this is reported as a negative result, not hidden.
- **The physics model is a documented simplification** of a full thermomechanical SMA constitutive law (§9).
- **No real FEM/COMSOL coupling anywhere.**
- Sample sizes in the data-efficiency and noise-robustness experiments are modest (3 seeds per condition) — the trends are consistent and physically sensible, but individual percentages should be read as suggestive, not tightly bounded.

## 13. What changed on the second audit pass (read this if you're deciding whether to trust the numbers above)

An earlier version of this project reported a "~13% OOD RMSE improvement from the physics residual, robust across seeds." A subsequent audit found two real methodology bugs behind that number:

1. **`physics_weight` was selected by observing performance on the exact same OOD test set later used to report results** — hyperparameter tuning that leaks into the test set.
2. **"In-distribution RMSE" was computed by predicting on the training set itself**, not a held-out split — training error reported as generalization error.

Both were fixed: a genuinely held-out ID test split was added (`interior_train_val_test_split_sma`), and a separate validation OOD set disjoint from the final test set was added (`ood_shell_dataset`) for hyperparameter selection. Under the corrected methodology, the diameter-RMSE improvement **did not survive** — it's noise-level at every `physics_weight` tried. The martensite-fraction recovery improvement **did survive**, fully intact, at every weight tested. The corrected, final numbers are what's reported in §10 and RESULTS.md.

Separately, the same audit found the patient-growth generator's `Valve_t0` was drawn independently of every feature (correlation ≈ 0.02–0.07, noise-level), making roughly half the benchmark's two-column target unlearnable regardless of model capacity, and that `Height_cm`/`Weight_kg` were independent of `Age_yrs` (a synthetic "1-year-old" could be assigned a height of 180cm). Both were fixed (§4); the leaderboard's R² went from ≈0.01 (barely above predicting the mean) to ≈0.70 as a direct result. The same pass found `MLPRegressor` was being fed unscaled features and produced R² ≈ −7 (worse than predicting the mean) — a missing-preprocessing bug, not evidence MLPs are unsuited to this task; fixed by standardizing inputs and outputs, after which `mlp` performs on par with `linear`/`ridge`.

Full details, every number before and after, and the reasoning behind each fix are in RESULTS.md and JOURNAL.md.

## 14. Future work

- Real public-dataset ingestion for VALVEBENCH (the loaders exist; the data doesn't).
- Transcribing real Pettersen/Zilberman tables and a verified Hoashi/Zhang formula.
- Forward transformation kinetics and temperature dependence in the SMA model.
- A geometric (strut/lattice) model connecting material strain to device diameter, replacing the current recovery-fraction indirection.
- Larger seed counts for the data-efficiency/noise-robustness sweeps.
- Real FEM (COMSOL) coupling as a ground truth to train/validate the surrogate against, instead of a fully synthetic generator.
